## 三、降级方案（你说了不是硬需求，这里是每一环的兜底）

| 环节 | 正常 | 降级 1 | 降级 2（最终保底） |
|---|---|---|---|
| **AI 分组凑不满** | 官方源 4 + HN 6 | HN 降到 ★≥10（实测可得 16 条） | 用**中文 AI 源**补（实测 24 条候选：量子位/爱范儿/InfoQ/掘金/Solidot） |
| **官方博客 0 条**（常见） | 取 1-2 条 | 由 HN 顺延 | 由中文源顺延，**保证总数 20** |
| **DeepSeek 不可用** | 中文摘要 | 用源自带描述（中文源直接可用） | **英文原题 + 链接**（不阻断推送） |
| **飞书卡片推送失败** | 交互卡片 | **纯文本消息**（`msg_type=text`） | 写本地 Markdown 文件（日志留痕，内容不丢） |
| **某源挂了** | 正常解析 | 该源独立 try/except，返回空 | 其余源继续，**绝不整批失败** |
| **Trending 改版解析为 0** | 5 条 | 记告警日志 | 用 HN 里的 GitHub 链接补位 |
| **周末/长假** | 24h 时窗 | 周一自动放宽到 72h | 上限 72h，避免旧闻当新闻 |
| **无新内容** | 正常推送 | **不推空卡片**，只记日志 | 退出码 0 |

**关于「不用 LLM」的结论**：如果你连 DeepSeek 也不想调，**效果依然可接受**——因为第 1 档里有 **6 个中文源（实测 45 条/24h 候选）**，标题本身就是中文。那样日报的形态是「中文标题 + 链接 + 源自带摘要」，省掉摘要润色，效果大约打 7 折，但**零成本、零 API、零 Key**。

## 五、实现要点（已验证）

1. **零第三方依赖**：`urllib` + `xml.etree` + `re` + `html` + `json` + `hmac`，全部标准库。
2. **RSS/Atom/RDF 三格式兼容**：一个解析器搞定 23 个源（含 RSS1.0 默认命名空间陷阱）。
3. **内置 XML 容错**：`re.sub` 清非法控制字符 + 转义裸 `&`（2 行，机器之心就是被这个卡住，但清洗后仍失败故排除）。
4. **URL 归一化去重**：过滤 23 个跟踪参数 + 默认端口 + 末尾斜杠；**注意不要对 path 做小写化**（GitHub 仓库大小写敏感）。
5. **AI 关键词用词边界匹配**：子串匹配实测 13 用例错 8 个（`said`/`chair`/`domain`/`Thailand` 全误命中）。
6. **飞书加签**：官方算法已验证（`key=f"{ts}\n{secret}"`、`msg=b""`、秒级时间戳）。
7. **卡片**：20 条实测 27 个元素 / 4.7 KB，远低于 200 元素与 20 KB 上限，**无需分片**。
8. **成功判定**：必须 `code == 0`（HTTP 200 也可能是失败）。
9. **计划任务时刻**：**08:35**（避开整点/半点，防 11232 限流）。
