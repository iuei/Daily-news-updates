# 飞书自定义机器人加签算法 · 仲裁结论

> 关键突破：`open.feishu.cn` 是前端渲染页，但页面带 `<link rel="alternate" type="text/markdown">`，其 `.md` 纯文本版可直接下载 → **本次拿到了官方原文**。辅以多独立实现交叉验证 + 本地实算比对。

## 结论（一句话，明确站哪一边）

**两个信源是同一个算法，谁都没错。官方原文的物理归类是「key = `"{ts}\n{secret}"`，被签消息 = 空字节串 `b""`」（即信源2 的字面写法）；信源1 的 Python 代码是官方示例的逐字照抄，`msg` 缺省即 `b""`，与信源2 输出逐位相同。**

```text
HMAC-SHA256(key = b"",               msg = "1599360473\ndemo") = l1N0gAcBjdwBvGm1xMjOF0XSyaLRpR7tuO5dHfhAYc8=
HMAC-SHA256(key = "1599360473\ndemo", msg = b"")               = l1N0gAcBjdwBvGm1xMjOF0XSyaLRpR7tuO5dHfhAYc8=
```

⚠️ 纠正误读：信源1 注释说「secret 放在待签消息里」，但**代码**并非 `key=secret, msg="{ts}\n{secret}"`。Python `hmac.new` 第二位置参数是 `key`（`inspect.signature(hmac.new)` → `(key, msg=None, digestmod='')`），`msg` 省略 → `b""`；故信源1 实际运算 = `key="{ts}\n{secret}", msg=b""`。

## 官方文档原文摘录（含 URL 与原文代码块）

来源：https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot.md （人读页 https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot ）；Lark 国际版同内容 https://open.larksuite.com/document/client-docs/bot-v3/add-custom-bot

**官方算法描述（逐字）：**

> 将`timestamp + "\n" + 密钥`当做签名字符串，使用 HmacSHA256 算法**计算空字符串**的签名结果，再进行 Base64 编码。其中，`timestamp`是指距当前时间不超过 1 小时（3600 秒）的时间戳，时间单位：s。例如，1599360473。

**官方 Python 示例（逐字摘录）：**

```Python
def gen_sign(timestamp, secret):
    # 拼接timestamp和secret
    string_to_sign = '{}\n{}'.format(timestamp, secret)
    hmac_code = hmac.new(string_to_sign.encode("utf-8"), digestmod=hashlib.sha256).digest()
    # 对结果进行base64处理
    sign = base64.b64encode(hmac_code).decode('utf-8')
    return sign
```

**官方 Java / Go 示例（同文件）——key/msg 归属的铁证，被签名数据均为空：**

```text
Java: stringToSign = timestamp + "\n" + secret;
      mac.init(new SecretKeySpec(stringToSign.getBytes(UTF_8), "HmacSHA256"));
      byte[] signData = mac.doFinal(new byte[]{});        // ← 被签名数据为空
Go:   stringToSign := fmt.Sprintf("%v", timestamp) + "\n" + secret
      var data []byte                                     // ← nil，零长度
      h := hmac.New(sha256.New, []byte(stringToSign)); h.Write(data)
```

**官方请求体字段位置（顶层，非 header）：** `{ "timestamp": "1599360473", "sign": "xxx", "msg_type": "text", "content": {"text": "request example"} }`

## 官方/权威 SDK 实现佐证（仓库 + 文件 + 代码）

- **官方 Python SDK `larksuite/oapi-sdk-python`（`lark-oapi` 1.7.5）不含自定义机器人 webhook 加签实现**：实测其 `hmac` 仅用于**事件订阅**签名（`x-lark-signature = SHA256(timestamp+nonce+encrypt_key+body)`）与 verification_token 比较，属另一套机制。故本项**无法用官方 SDK 佐证**，官方文档本身即最高权重证据。
- **独立测试向量（金标准）**：`go-lark/lark` v2.0.1（Go 社区 SDK，https://github.com/go-lark/lark ）`crypto.go::GenSign` 与官方 Go 示例逐字一致，其 `crypto_test.go` 给出固定期望值：

```go
sign, _ := GenSign("xxx", 1661860880)
assert.Equal(t, "QnWVTSBe6FmQDE0bG6X0mURbI+DnvVyu1h+j5dHOjrU=", sign)
```

**本地实算比对（本次真实执行）：** 上式用官方算法实算 **✅ 一致**；官方 Java demo `secret="demo", ts=1599360473` 官方未给期望值，实算得 `l1N0gAcBjdwBvGm1xMjOF0XSyaLRpR7tuO5dHfhAYc8=`。官方**未提供** `secret+timestamp → 期望 sign` 的比对样例（Java demo 只 `printf`），故 go-lark 向量是可判定的金标准。

## 两种候选算法的对照与判定依据

| 项 | 信源1 字面 | 信源2 字面 | 说明 |
|---|---|---|---|
| Python 写法 | `hmac.new(string_to_sign.encode(), digestmod=sha256)` | `hmac.new(string_to_sign.encode(), b"", sha256)` | **完全等价**：前者 msg 取默认 `b""` |
| HMAC key | `b""` | `"{ts}\n{secret}"` | 官方 Java `mac.init(...)`、Go `hmac.New(sha256.New, ...)` 第 1 参 → key |
| HMAC msg | `"{ts}\n{secret}"` | `b""` | 官方 Java `doFinal(new byte[]{})`、Go `var data []byte` → 空 |
| 实算值（`ts=1599360473, secret="demo"`） | `l1N0gAcBjdwBvGm1xMjOF0XSyaLRpR7tuO5dHfhAYc8=` | 同左 | ✅ **相等** |

**判定依据**：(1) 官方原文 + 三语言示例（Java/Go 的 msg 是空数组，Python 的 msg 取默认空值）→ 铁证；(2) Gitea 与 go-lark 两个独立生产实现输出同值；(3) go-lark 固定测试向量经本地实算通过；(4) 信源1 与信源2 实算逐位相同。
**必须避免的第三种错法**：`HMAC-SHA256(key="demo", msg="1599360473\ndemo") = DkEDUyVoOOJ539qBvUgMyzkzIdRWlf4e/V3Rq+ONJnQ=` ≠ 官方值 `l1N0gAcBjdwBvGm1xMjOF0XSyaLRpR7tuO5dHfhAYc8=`

## 可直接使用的 Python 标准库实现（≤20 行，带注释：timestamp 单位、字段位置）
```python
import hashlib, hmac, base64, time

def gen_sign(timestamp, secret):
    """飞书自定义机器人加签。timestamp: 秒级（距请求 ≤1 小时，单位 s）；
    key = f"{timestamp}\\n{secret}"，被签消息 = 空字节串 b""（HMAC-SHA256）。"""
    string_to_sign = f"{timestamp}\n{secret}"                      # 待签名串
    digest = hmac.new(string_to_sign.encode("utf-8"), b"", digestmod=hashlib.sha256).digest()
    return base64.b64encode(digest).decode("utf-8")

ts = int(time.time())                       # 秒级；不要用毫秒
body = {                                    # timestamp / sign 放【请求体顶层】，不是 header
    "timestamp": str(ts),                   # 官方示例为字符串（int 实测亦可，建议跟官方）
    "sign": gen_sign(ts, SECRET),
    "msg_type": "text", "content": {"text": "hello"},
}
# requests.post(WEBHOOK_URL, json=body)     # Content-Type: application/json
```

## 错误码与安全设置模式

**字段与位置（官方确认）**：`timestamp` 单位**秒（s）**，距当前时间**不超过 1 小时（3600 秒）**，否则签名过期；位于**请求体顶层**（字段名 `timestamp` + `sign`，与 `msg_type`/`content` 同级），**不是 header**；请求体 ≤ 20 KB。

| 错误码 | 含义 | 来源 |
|---|---|---|
| `19021` | `sign match fail or timestamp is not within one hour from current time`（签名失败/时间戳超 1h） | ✅ **官方原文**（add-custom-bot.md） |
| `19022` | `Ip Not Allowed`（IP 白名单校验失败） | ✅ **官方原文**（同文件"方式二"） |
| `19024` | `Key Words Not Found`（关键词未命中） | ✅ **官方原文**（同文件"方式一"）；实测见 https://github.com/megaease/easeprobe/issues/468 |
| `9499` | `Bad Request`；**webhook token 无效/失效走 9499**（`StatusCode: 9499, "invalid hook"`） | ✅ 官方给 `9499 Bad Request`；`invalid hook` 见 https://docs.superun.ai/superun/skills/feishu/feishu-robot |
| `19001` | ❌ **不是"webhook token 无效"**，社区一致指向**应用机器人权限错误** `no permission to send message`（缺 `im:message:send_as_bot`） | ⚠️ https://docs.superun.ai/superun/skills/feishu/feishu-robot ；`19001` **不在**官方错误码表 https://open.feishu.cn/document/ukTMukTMukTM/ugjM14COyUjL4ITN.md （该表仅到 `19002`/`19036`） |

> **对线索的更正**：`19001` 疑为签名失败**不成立**——签名失败是 `19021`；自定义机器人 URL/token 失效是 **`9499` + `invalid hook`**。脚本失败分支应判 `code ∈ {19021, 19022, 19024, 9499}`。另：`19024` 在**应用机器人**语境下另有"机器人不在目标群中"之义（同 superun 文档），与自定义机器人的"关键词未命中"同码不同义。

**安全设置三种模式：可叠加，不是三选一。** 官方原文逐字："在同一个自定义机器人中，**你可以设置一个或多个方法**。" 三种为 自定义关键词 / IP 白名单 / 签名校验；可同时启用（如签名校验 + IP 白名单），启用后**每项都须通过**；关键词最多 10 个、IP 最多 10 条。

## 仍不确定的部分（如有）

1. **官方未提供"固定 secret+timestamp → 期望 sign"样例值**（Java demo 只 `printf` 不比对）；本次采用 go-lark 公开测试向量 `("xxx", 1661860880) → QnWVTSBe6FmQDE0bG6X0mURbI+DnvVyu1h+j5dHOjrU=` 作金标准并通过实算，**该向量源自社区，非飞书官方**。
2. **`timestamp` 传字符串还是数字**：官方 JSON 用字符串 `"1599360473"`，社区多传 int，实测两者均可用；建议跟官方用字符串。
3. **两处仅社区可证**：官方错误码表中**不存在 `19001`**，"缺 `im:message:send_as_bot` 权限"来自 https://docs.superun.ai/superun/skills/feishu/feishu-robot ，**未经官方原文确认**；`9499` 的 `invalid hook` 同样来自该社区文档（官方原文仅给 `9499 Bad Request`）。如需 100% 确认，应用无权限的应用机器人实测复现。
4. `open.larksuite.com` 国际版本次经 `web_fetch` 无法直连（本地 DNS 代理返回非公网 IP），已改用 `open.feishu.cn` 的 `.md` 端点取得官方原文；Lark 版 `.md` 与中文版内容一致（含相同 Java/Go/Python 示例）。
